# PaperLens 简历项目介绍

## 版本一：完整版（项目经历栏，6 条）

**PaperLens：论文检索与分析 Agent**　｜　个人项目　｜　Python · LangGraph · Milvus · FastAPI · Streamlit

基于 RAG 与 LangGraph 的本地论文知识库助手：支持 arXiv 论文 / PDF 入库，中英文带引用问答、单篇解读卡片、多篇对比；本地证据不足时联网检索 arXiv，经用户确认后补充入库。

- **结构化解析与分块**：解析 arXiv HTML（LaTeXML）的章节树与段落锚点，无 HTML 时回退 PDF 解析；按章节分块，表格单独成块，并为每块加上「论文标题 | 章节路径」上下文标题，回答中的引用可跳转到原文对应段落。
- **混合检索**：在 Milvus 中用内置 BM25 Function 与 bge-m3 稠密向量实现混合检索，RRF 融合后接 bge-reranker 重排；中文提问时 BM25 通道改用 LLM 生成的英文检索句，实现中文问题检索英文论文。
- **Agent 编排**：用 LangGraph 状态图实现意图路由（问答 / 解读 / 对比 / 找论文 / 闲聊）与证据判定；本地证据不足时检索 arXiv，用 reranker 过滤噪声候选，通过 `interrupt` 由用户确认后入库并重新回答；`SqliteSaver` 持久化会话，支持指代消解与跨进程恢复。
- **长上下文与结构化生成**：单篇论文整篇送入长上下文，抽取 JSON 解读卡片（问题 / 方法 / 实验 / 结果 / 局限），每条要点标出处并校验锚点；多篇对比基于卡片二次生成，输入 token 降低一个数量级；生成后校验引用编号，剔除越界引用，提示词隔离外部内容以防注入。
- **评估与消融**：自建 30 篇论文、50 题测试集（含术语题、跨语言题和 10 道语料外问题），池化标注相关块；逐级消融显示 Recall@5 从纯稠密检索的 65.0% 提升到 84.0%、MRR@10 从 0.749 提升到 0.967；端到端回答正确率 95%，引用编号合法率 100%。评估中定位并修复了论文名称误匹配导致检索范围错误的问题（正确率 92.5% → 95%）。
- **工程化**：FastAPI 提供 SSE 流式问答、后台入库任务队列与 PDF 上传（可选 API Key 鉴权），Streamlit 实现问答 / 论文库 / 对比 / 检索调试四个页面；统计每次调用的 token 与费用（单次问答约 ¥0.003）；96 个单元测试覆盖解析、检索、Agent 各路由分支、API 与评估指标。

## 版本二：精简版（3 条，篇幅紧张时用）

**PaperLens：论文检索与分析 Agent**　｜　Python · LangGraph · Milvus · FastAPI

- 解析 arXiv HTML 的章节与段落锚点并按章节分块；用 Milvus 内置 BM25 + 稠密向量混合检索，RRF 融合后重排，中文提问时 BM25 用 LLM 改写的英文查询；在自建 50 题测试集上 Recall@5 从 65.0% 提升到 84.0%，端到端回答正确率 95%。
- 用 LangGraph 状态图编排意图路由、证据判定与联网补充：证据不足时检索 arXiv，经 `interrupt` 人工确认后入库重答；`SqliteSaver` 支持多轮追问。
- 单篇论文用长上下文生成带出处的结构化解读卡片，并基于卡片生成多篇对比表；FastAPI（SSE）+ Streamlit 提供 Web 服务，96 个单元测试。

## 面试可能被追问的点

**1. 为什么要做混合检索，不只用向量？**
论文里大量术语和缩写（如 IsRel、CRAG、Table 3），稠密向量对这类精确词面匹配不稳定，BM25 擅长；反过来，换一种说法问时 BM25 召回不到，稠密向量能召回。两路用 RRF 按排名融合，不需要把两种分数归一化到同一量纲。

**2. 中文问题怎么检索英文论文？**
bge-m3 是多语言嵌入，稠密通道直接用中文原问题。BM25 是词面匹配，中文词对不上英文原文，所以让 LLM 在查询分析时顺带输出一句英文检索句给 BM25 用。这一步和意图识别、指代消解合在同一次 JSON 调用里，不额外增加延迟。

**3. 为什么用状态图，不用 ReAct 让模型自己决定？**
问答流程基本固定，写成状态图后每一步可单测、延迟和成本可预期。真正需要判断的只有「证据够不够、要不要联网」，用条件边表达就够了。自由 ReAct 每轮都要模型决定调用哪个工具，更慢、更贵，也更难调试。

**4. 证据不足怎么判断？会不会误判？**
用重排的最高分对比阈值（0.3），另外要求问题里点名的论文都在库里。在测试集上扫了 0.05–0.5 五档：0.1–0.2 时判定准确率最高（96%），0.3 时 94%，多误拒了 1 道可回答题；10 道语料外问题有 2 道分数偏高（0.32、0.75，问的是 DPO、Llama 3 这类和语料主题很近的问题），但生成阶段按提示词回答了“资料未提及”，没有编造。测试集只有 50 题，所以没急着改默认值。

**5. 联网找到的候选论文噪声大怎么办？**
arXiv 关键词检索确实很杂，实测搜 "FLARE" 排第一的是联邦学习论文。做法是让 reranker 按「用户问题 vs 候选标题 + 摘要」打分，低于 0.05 的过滤掉，过滤后只剩正确的那篇（0.99）。

**6. 解读卡片为什么不用 RAG？**
单篇论文全文大多 1–2 万 token，长上下文模型一次就能读完。实验设置、局限这类信息常分散在正文和附录里，检索 Top-k 片段容易漏。卡片生成一次约 ¥0.02，结果缓存，之后读取不再花钱。跨论文的问题全文放不下，才用 RAG。

**7. 怎么防止模型编造引用？**
三层处理。第一，证据编号后放进 `<evidence>` 标签，要求每个陈述标编号，证据没有的内容回答「未提及」。第二，生成后校验引用编号，越界的直接删掉。第三，卡片里的出处锚点必须在原文中真实存在，否则清空。

**8. Milvus Lite 只能单进程打开，Web 服务怎么设计的？**
FastAPI 作为唯一持有存储的进程，Streamlit 只通过 HTTP 调用它。入库放进单线程任务队列串行执行，同时满足 arXiv 3 秒请求间隔的要求。问答在后台线程里跑，事件经队列转成 SSE 推给前端，客户端断开也能跑完，会话状态保持完整。

**9. 测试集怎么建的？Recall 可信吗？**
LLM 依据随机抽取的块出题，我逐题对照原文核对答案，改写了 10 道指代不清的题（如“用 T5 的那篇论文”）。相关块用池化标注：五个配置各取 top-10，并集交给 LLM 对照参考答案判断是否包含答案，平均每题 2.4 个相关块。这样 Recall 只在被池化的块里算，是相对值，适合比较配置之间的差异，不能当成绝对召回率。

**10. 消融里哪一步收益最大？**
重排最大：Recall@5 从 71.8% 到 84.0%，MRR 从 0.874 到 0.967，代价是每次多 0.45 秒。上下文标题 +4 个点；BM25 + RRF 主要改善排序。英文检索句的作用在中文题和术语题上：BM25 换回中文原问题后，中文题 Hit@5 从 100% 降到 95.5%，术语题从 100% 降到 90%。

**11. 评估发现了什么问题？**
问“RAG 论文里 RAG-Sequence 的两种解码方式”时被拒答。原因是名称解析按子串匹配，“RAG” 命中了 “Leve**rag**ing Passage Retrieval…”，检索被限定在 FiD 那篇论文里。改成从单词开头匹配，并且一个名称匹配到多篇论文时视为泛称、不限定范围，正确率从 92.5% 升到 95%。

## 使用建议

- 简历里的数字都来自 [eval/reports/report.md](../eval/reports/report.md)，可以用 `paperlens eval --answers` 复现（DeepSeek 非高峰时段约 ¥0.3）。测试集只有 50 题，面试时如实说规模，并说明 Recall 是池化标注下的相对值。
- 面试时可以现场演示 Web 端：问一个库里没有的论文 → 确认入库 → 回答并点击引用跳到原文段落。这一段最能体现项目的完整度。
